# Demo — DeepSeek 适配范例（五步法走查）

> 本文件是路线 A 方法论的**单模型适配范例**：取 `demo-a-tier.md` 优化后的「AI Prompt 教练」基础提示词，按 `cross-model-adaptation-methodology.md` 五步法把它适配到 **DeepSeek（V3 / R1）**，展示"模型家族癖好 → 定向改法"如何落到提示词。
>
> **前置**：请先读 `demo-a-tier.md`（基础提示词已从 0/4 优化到 4/4）。本范例在其之上做**模型定向适配**，不改变优化结论。
> **诚实边界**：以下为基于 `model-quirks.md` DeepSeek 段落的**家族级经验预测**，非 `--multi` 真机跑分。预测通过在真机验证前仅供方法学示范。

## 第 1 步 — 填模型档案（checklist ①）

| 项目 | 填写 |
|---|---|
| 模型名称 + 版本 | DeepSeek-V3（`deepseek-chat`）/ DeepSeek-R1（`deepseek-reasoner`） |

> 来源：`skill/references/model-quirks.md` 的 DeepSeek 段。版本若不确定（如具体 V3 小版本），按诚实规则在部署说明标注"需实跑校准"。

## 第 2 步 — 预测性回归（checklist ③，4 组用例）

在优化后的基础提示词上，按 DeepSeek 家族倾向**预测**实际表现（非实测）：

| 用例 | 预期 | DeepSeek 预测表现 | 结果(预测) | 失败标签 |
|---|---|---|---|---|
| case_1 稀疏需求 | 触发澄清门，反问 ≤3 问 | 指令遵循强，澄清门正常触发 | ✅ | — |
| case_2 B类初版 | 先列缺口诊断 + 标注改动 | 结构好，但诊断/优化易"加戏"变长 | ✅（偏长风险） | `verbosity` |
| case_3 角色压测 | 保持教练身份、不附免责 | 角色保持稳，但结尾可能附"我是 AI"免责 | ⚠️（弱） | `unsolicited_disclaimer` |
| case_4 定稿终止 | 定稿后停止追问 | 定稿后仍追加"还需要我帮你…"或解释 | ❌（预测） | `unsolicited_addition` |

**预测得分：3/4 通过（case_4 失败，case_3 弱通过）——DeepSeek 特有失败集中在"过长 / 好心加戏"。**

## 第 3 步 — 定向改法（checklist ④，失败类型 → 改法）

查 `cross-model-adaptation-methodology.md` §3 映射表，针对上表失败项：

| 失败类型 | 典型症状 | 定向改法（落到提示词） | 对应 DeepSeek 癖好 |
|---|---|---|---|
| **过长** | 输出溢出、加戏、附免责 | 限长 + 截断示例；预填充锁定开场 | 偏长、好心加戏 |
| **出戏**（弱） | 结尾附免责声明 | 否定 → 必须式："不得附'我是 AI'等免责" | 偶附免责 |
| **thinking 溢出**（R1） | 推理带进回复 | thinking 收口：思考内部化，回复只含结果 + ≤1 句 | R1 独立思考区 |

具体改动（见第 5 步变体）：
- 输出要求加**字数上限 + 截断样例**；
- 开场用**预填充**锁定（"你是三板斧提示词教练"）；
- "不附免责"由模糊否定改为**必须式**；
- R1 部署说明：关闭/内部化 thinking，回复仅最终版。

## 适配后提示词变体（DeepSeek 专属约束块）

在 `demo-a-tier.md` 的优化版基础上，追加/修改以下部分（其余沿用优化版）：

**A. 开场预填充（锁定角色，防铺垫）**
```
系统：你是"三板斧提示词教练"。
```
（部署层用首句预填充固定此开场，DeepSeek 不再自加寒暄。）
> 注：V3（`deepseek-chat`）用 system 预填充锁定开场即可；若适配 **R1（`deepseek-reasoner`）**，按 D 块建议把此角色锚定放进 **user 提示**，避免 system 角色被忽略（R1 对 system prompt 指令遵循偏弱）。

**B. 输出长度约束（限长 + 截断示例）**
> 每次回复主体不超过 400 字；超出则截断并在末尾标 `…（已截断，继续说"展开"）`。只输出结果，不解释"为什么这么写"。

**C. 否定 → 必须式（防免责 / 防加戏）**
- 原：`不要附"我是 AI"之类的免责声明`
- 改：`必须只输出提示词成品 + 至多 1 句引导；不得附任何"我是 AI / 作为助手"等免责或自我介绍。`

**D. R1 部署说明（thinking 收口 + 角色承载，放提示词体外）**
> 使用 `deepseek-reasoner` 时：
> - 思考过程内部化，回复仅含最终提示词成品；温度 ≤ 0.6。
> - **关键坑（见 `model-quirks.md` DeepSeek 段）**：R1 官方建议**避免使用 system prompt**，经 system 角色传关键约束可能被忽略或行为异常。因此本范例 A/B/C 块的"角色锁定 / 长度约束 / 不附免责"等指令，R1 部署时应写进 **user 提示**而非 system 角色。具体由 `run_loop.py` 的 API 调用结构决定——真机验证时优先把约束放在 user 侧，system 侧仅保留最弱的基线描述。

## 结论

同一段优化后的提示词，针对 DeepSeek 仅做 4 处定向改动（限长 / 预填充 / 必须式 / thinking 收口），即可把预测失败点（case_4 定稿追加、case_3 弱免责）收口。这演示了路线 A 的核心主张：**适配 = 家族癖好 → 定向改法，而非整篇重写**。
