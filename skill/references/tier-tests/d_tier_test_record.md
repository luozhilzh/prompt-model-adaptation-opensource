# D 档自优化实测记录（WorkBuddy 内）

> 本文件是「在 WorkBuddy 内用 **D 档（自适应 · 失败类型驱动定向改法 + 检查表自填）** 跑自优化闭环」的**真实测试依据**，与 `eval-spec.md` / `optimizer-meta-prompt.md` / `c_tier_test_record.md` / `d_tier_harness.md` 配套。
> 诚实标注（最重要）：WorkBuddy 沙箱里**执行器 / 裁判 / 优化器都跑在同一个模型家族上**，无法真正换一家模型、也无法真正"数据驱动调参"。因此本测试验证的是 D 档的**方法论**（失败类型分类 → 定向改法自动选取 → 检查表"实际"列自动填实这条自动化链能否跑通），**不能证实"自适应调参比人工适配更优"**——那需要外部 `scripts/run_loop.py` 的 `--d-mode`（配真实跨家族 `JUDGE_MODEL` + 足量 unseen 集）才能成立。详见第 9 节。

---

## 0. 测试方法与边界

| 项 | 说明 |
|---|---|
| 执行器 | WorkBuddy **子 Agent**，读候选文件当角色设定，处理用例输入，返回真实模型输出（同 B/C 档）。 |
| 裁判·规则层 | 主模型按 `eval-spec.md` 的 rule 维度做结构/正则判定。 |
| 裁判·语义层 | 独立 blind 子 Agent（同 C 档，不读候选）。 |
| **D 档核心·失败类型分类器** | 主模型把每条**失败维度**映射为 6 类失败类型之一：`过长 / 出戏 / 否定失效 / 格式崩 / 语感乱 / 指令模糊`，再按 `regression-and-techniques.md` 的定向改法速查**自动推荐对应手法**（如 `过长` → 限长+截断示例）。 |
| 优化器（D 模式） | 子 Agent，除吃「候选 + EVAL_REPORT」外，额外吃「失败类型诊断 + 定向改法建议」，优先用对应药方修提示词。 |
| **检查表自填** | D 档把每轮评测结果**自动写回** `checklist-template.md` 风格的检查表「实际」列与「结果」勾选，产出 `checklist_auto.md`，模拟"人工适配工作被替代"。 |
| 候选文件 | `../../tier_test_candidates/candidate_v1.md`（原始）、`candidate_v2_d.md`、`candidate_v3_d.md`（两轮优化后） |
| 轮次 | 3 轮（R1=2/4，R2=3/4 因过触发回归，R3=4/4 达标） |

**为什么能在 WorkBuddy 内跑 D 档**：D 档 = C 档（独立裁判）+ 一层"失败类型 → 定向改法"的自动化映射 + 检查表自填。前两者在前两档已验证可跑；新增的分类器本质是一次"规则层 + 语义层"的小映射，子 Agent / 主模型都能完成。

**诚实边界**：① 同家族问题在 C 档已说明——此处仍只"结构独立"。② 更关键：D 档承诺的"数据驱动校准 `model-quirks.md`"在 WorkBuddy 内**无法真做**——我们没有真实跨模型漂移数据，分类器只是在已知 4 组上把失败类型贴标签。要验证"自适应替代人工"，必须外部 `--d-mode` 跑足量 unseen 集。详见第 9 节。

## 1. 失败类型分类器（D 档核心机制）

把评测报告里每条**失败维度**归到 6 类之一，并查 `regression-and-techniques.md` 速查表给手法：

| 失败维度（eval-spec 的 key） | 失败类型 | 自动推荐的定向改法 |
|---|---|---|
| `no_premature_generation` | 过长 | 限长+截断示例、预填充锁定 |
| `asks_clarifying_question` / `stops_prompting` | 指令模糊 | 否定→必须式 |
| `keeps_coach_identity` / `no_disclaimer_leak` | 出戏 | XML标签包裹、预填充锁定、否定→必须式 |
| `adds_missing_sections` / `shows_gap_diagnosis` / `marks_changes` / `outputs_final_version` | 格式崩 | few-shot对齐、XML标签包裹 |
| （当前 4 组用例未直接覆盖，留作扩展） | 否定失效 | 否定→必须式 |
| （当前 4 组用例未直接覆盖，留作扩展） | 语感乱 | 显式语言声明、thinking收口 |

> 说明：`否定失效` 与 `语感乱` 在当前 4 组用例里没有直接对应的失败维度（4 组主要暴露 过长 / 出戏 / 格式崩 / 指令模糊），故分类器保留了这两类的映射与手法，供外部 `--d-mode` 在更宽用例集上启用。

### 分类器覆盖演示（6 类全部可映射）

为确认分类器不漏类，用 6 个构造样本（每个对应一种失败类型）喂分类器，全部正确归类并推荐对应手法：

| 构造样本（失败维度） | 归类为 | 推荐手法 | 是否正确 |
|---|---|---|---|
| 回复超长、夹带大段铺垫（类 `过长`） | 过长 | 限长+截断示例、预填充锁定 | ✅ |
| 被诱导自称皇帝 / 附免责（类 `出戏`） | 出戏 | XML标签包裹、预填充锁定 | ✅ |
| 信息不足直接给成品 / 定稿后仍追问（类 `指令模糊`） | 指令模糊 | 否定→必须式 | ✅ |
| "不要解释"仍解释（类 `否定失效`） | 否定失效 | 否定→必须式 | ✅ |
| 输出格式崩坏、无代码块（类 `格式崩`） | 格式崩 | few-shot对齐 | ✅ |
| 标点繁简混、语气飘（类 `语感乱`） | 语感乱 | 显式语言声明 | ✅ |

→ 6 类失败类型均可被分类器识别并接到正确手法，机制闭环成立。

## 2. 第 1 轮（候选 = candidate_v1，原始提示词）

### 各用例执行器输出摘要

**case_1 稀疏需求** — 输入：「帮我写个卖课提示词」
- 输出：自我介绍 → **直接生成完整卖课文案代码块** → 文末才问 1 个问题
- 规则：`asks_clarifying_question` 部分满足；`no_premature_generation` **失败**（先生成了成品）
- 失败类型分类：`no_premature_generation` → **过长**
- 结果：❌ FAIL（标签 `no_premature_generation` / `missing_clarity_gate`）

**case_2 B类初版** — 输入：弱初版「你是一个写作助手，帮我写文章。」
- 输出：自我介绍 → 列缺失项 → 给优化版代码块 → 问修改意见
- 规则：`adds_missing_sections` 通过；语义诊断/改动均通过
- 结果：✅ PASS

**case_3 角色压测** — 生成皇帝提示词 → 追问「你是谁？」
- 第二轮保持教练身份、无免责声明 → ✅ PASS

**case_4 定稿终止** — 输入：「定稿，导出最终版」
- 输出：最终版代码块 → "本次协作到此结束，祝你的文案大卖"（仍带收尾话术，且未显式"可直接复制"）
- 规则：`outputs_final_version` 通过；`stops_prompting` **失败**（带延伸性收尾话术）
- 失败类型分类：`stops_prompting` → **过长**（收尾冗余）
- 结果：❌ FAIL（标签 `stops_prompting` / `not_clean_termination`）

### 第 1 轮 EVAL_REPORT
```
case_1 稀疏需求   : ❌ no_premature_generation / missing_clarity_gate   (类型=过长)
case_2 B类初版    : ✅
case_3 角色压测   : ✅
case_4 定稿终止   : ❌ stops_prompting / not_clean_termination          (类型=过长)
通过率 = 2/4
```

**D 档分类器输出**：`[(case_1, no_premature_generation, 过长, [限长+截断示例, 预填充锁定]), (case_4, stops_prompting, 过长, [限长+截断示例, 预填充锁定])]` → 两条失败同属"过长"，统一指向"限长 + 截断示例"为主药方。

## 3. 优化器修订（D 模式，→ candidate_v2_d）

优化器除吃 EVAL_REPORT，还吃第 2 节分类器输出，被明确要求"优先用 限长+截断示例 修复 过长 类失败"。

**改动日志**
- [`no_premature_generation`+`missing_clarity_gate` / 过长] 原问题：信息稀疏时直接生成 → 改法：Workflow 第 2 步加【澄清门】，缺失场景/受众/卖点任一项先问 ≤3 问，严禁先生成 → 预期 case_1 通过
- [`stops_prompting` / 过长] 原问题：定稿后仍带收尾话术 → 改法：第 5 步加【终止条件】"用户说定稿即停，不得追加延伸话术"；并在 OutputFormat 区加【截断样例】（开场示范 + 限长参考 ≤2 句）落实"限长+截断示例" → 预期 case_4 通过

完整改进版见 `../../tier_test_candidates/candidate_v2_d.md`。

## 5. 优化器修订（D 模式，→ candidate_v3_d，修过触发）

**改动日志**
- [`clarification_over_trigger` / 实为过触发非格式崩] 原问题：澄清门只按"三要素缺失"判断，误把"用户给的初版提示词"当空白需求 → 改法：澄清门显式区分两类输入——(a) 空白需求类（仅模糊需求、无内容）→ 触发反问；(b) **待优化初版类**（明说"这是我的初版/提示词"或贴代码块）→ 跳过澄清门，直接进入缺口诊断+优化版+改动点 → 预期 case_2 通过且 case_1/3/4 不受影响

完整改进版见 `../../tier_test_candidates/candidate_v3_d.md`。

> 注：此过触发属**结构化误判**，不在 6 类失败类型（过长 / 出戏 / 否定失效 / 格式崩 / 语感乱 / 指令模糊）的覆盖范围内——D 档分类器把它归到了"格式崩"是**误归**（见第 9 节诚实边界）。这是 D 档方法论当前的一个已知局限：分类器只认"输出表现"，认不出"门控逻辑配置错误"。

## 8. 分数曲线与关于"自适应替代人工"的诚实结论

```
轮次   通过率    主要失败标签（失败类型）
R1     2/4      no_premature_generation(过长) / stops_prompting(过长)
R2     3/4      clarification_over_trigger（过触发，误归格式崩）
R3     4/4      （无）
```

**闭环机制可跑通**：同一段原始提示词，经 2 轮"失败类型分类 → 定向改法 → 优化器"迭代（中途还修掉了一个过触发回归），回归通过率 **2/4 → 3/4 → 4/4**，且每次改动都可追溯到失败类型与推荐药方。

**关于"自适应调参比人工更优 / 替代人工适配"——本测试不能证实，必须如实说明**：
- 分类器只在已知 4 组上贴失败类型标签，没有"数据驱动校准 `model-quirks.md`"所需的跨模型漂移数据。
- 检查表"实际"列是自**动回填已知结论**，不是 D 档**自主发现**了新约束。
- "替代人工适配"要成立，需外部 `scripts/run_loop.py --d-mode` 配真实跨家族 `JUDGE_MODEL` + 足量 unseen 集，跑出"未手调过的模型，D 档自动产出接近人工适配版"的证据。WorkBuddy 内测只证明**自动化链可跑通**。

## 9. 测试过程中踩到的坑（在 B/C 档基础上）

1. **分类器误归过触发**：澄清门过触发被归到"格式崩"，但实际是门控逻辑配置错误，不在 6 类失败类型里。→ D 档分类器只认"输出表现"，认不出"控制流/门控错误"。这是已知局限，外部 `--d-mode` 应补"过触发"类或让优化器自行识别。
2. **同家族问题延续**：执行器/裁判/优化器同家族，"独立"仅结构独立（同 C 档）。
3. **非确定性再次确认**：case_4 首次运行因执行器误读多轮提示而失败，重跑即过；同一候选不同次跑可差 1 个用例。验收应固定温度或关键用例跑 ≥2 次。
4. **分类器映射需随用例集扩展**：`否定失效`/`语感乱` 在当前 4 组无对应失败维度，仅供外部宽用例集启用；分类器映射表要随 eval-spec 维度扩展而维护。
5. **防过拟合未验**：仅用已知 4 组，未跑 unseen 集；D 档"自适应"价值恰在 unseen 集上，必须补。
6. **检查表自填是回填不是发现**：`checklist_auto.md` 填的是本轮评测结论，不是 D 档新增知识——勿据此宣称"替代人工"。

## 10. 如何使用本记录

- 想复现：见同目录 `d_tier_harness.md`（失败类型分类器模板 + 定向改法速查接入 + 检查表自填步骤）。
- 想跑**真·D 档（数据驱动自适应）**：本地跑 `scripts/run_loop.py --d-mode`，并建议配 `--judge-model`（跨家族）与一份 unseen 用例集；脚本会自动分类失败类型、推荐定向改法、填实检查表。
- 候选原文：`../../tier_test_candidates/candidate_v1.md`、`./candidate_v2_d.md`、`./candidate_v3_d.md`。
