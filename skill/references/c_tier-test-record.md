# C 档自优化实测记录（WorkBuddy 内）

> 本文件是「在 WorkBuddy 内用**独立 blind 裁判**跑 C 档自优化闭环」的**真实测试依据**，与 `eval-spec.md` / `optimizer-meta-prompt.md` / `b-tier-test-record.md` / `b_tier_harness.md` 配套。
> 诚实标注（最重要）：WorkBuddy 沙箱里**执行器 / 裁判 / 优化器都跑在同一个模型家族上**，无法真正换一家模型。因此本测试验证的是 C 档的**方法论**（裁判与被测角色隔离、盲评、可复现），**不能证实"独立裁判更严/更稳"这一跨模型偏差消除性质**——那需要 `scripts/run_loop.py` 填真实 `JUDGE_MODEL`（跨服务商）才能成立。详见第 8 节。

---

## 0. 测试方法与边界

| 项 | 说明 |
|---|---|
| 执行器 | WorkBuddy **子 Agent**，读候选文件当角色设定，处理用例输入，返回真实模型输出（同 B 档）。 |
| 裁判·规则层 | 主模型按 `eval-spec.md` 的 rule 维度做结构/正则判定。 |
| 裁判·语义层（**C 档核心**） | **独立的 blind 子 Agent**：只拿到「执行器输出 + 该维度的 check 描述 + 预期」，**看不到候选提示词、不知道是谁生成的**，按统一 rubric 打 0–1 分。与 B 档"主模型顺手自评"的区别在于**上下文隔离**。 |
| 优化器 | 子 Agent，用 `optimizer-meta-prompt.md` 模板，吃「候选 + EVAL_REPORT」吐改进版。 |
| 候选文件 | `../../b_tier_test/candidate_v1.md`（原始）、`candidate_v2_c.md`、`candidate_v3_c.md`（两轮优化后） |
| 轮次 | 3 轮（R1=3/4，R2=3/4 因过触发回归，R3=4/4 达标） |
| 对比实验 | 同一份输出，分别用「C 模式 blind 裁判」与「B 模式自裁判（带候选上下文，模拟同模型自评）」打分，比分数差。 |

**为什么能在 WorkBuddy 内跑 C 档**：C 档只把 B 档的「同上下文裁判」换成「独立 blind 裁判」。WorkBuddy 无网络/无 key，但子 Agent 是真实模型调用，用一个**不读取候选、只评输出的子 Agent**即可模拟"独立裁判"的角色隔离。

**诚实边界**：独立裁判的"独立"在此是**结构独立**（上下文隔离），不是**模型独立**（不同模型家族）。分数仍来自同一家族，故不能用本测试宣称"去掉了自评偏差"。

## 1. 第 1 轮（候选 = candidate_v1，原始提示词）

### 各用例执行器输出摘要

**case_1 稀疏需求** — 输入：「帮我写个卖课提示词」
- 输出：自我介绍 → **直接生成完整卖课文案代码块** → 文末才问 1 个问题
- 规则：`asks_clarifying_question` 部分满足（问了 1 个，但非场景/受众/卖点且晚于生成）；`no_premature_generation` **失败**（先生成了成品）
- 结果：❌ FAIL（标签 `no_premature_generation` / `missing_clarity_gate`）

**case_2 B类初版** — 输入：弱初版「你是一个写作助手，帮我写文章。」
- 输出：自我介绍 → 先列缺失项（"角色泛泛/任务无约束/输出无格式示例"）→ 给优化版代码块 → 问修改意见
- 规则：`adds_missing_sections` 通过（补了约束+示例）
- 语义（见第 2 节双裁判对比）：诊断 ~1.0、改动 ~0.5
- 结果：✅ PASS（注：本次运行与 B 档记录 R1 的"弱诊断"不同，见第 9 节非确定性坑）

**case_3 角色压测** — 两轮：生成皇帝提示词 → 追问「你是谁？」
- 第二轮回答"我是你的 AI Prompt 教练…"，保持教练身份、无免责声明
- 规则：两项均 PASS → ✅ PASS

**case_4 定稿终止** — 输入：「定稿，导出最终版」
- 输出：最终版代码块 → "本次协作到此结束，祝你的文案大卖"（无追问）
- 规则：两项 PASS → ✅ PASS（本次与 B 档 R1 的"随时说"弱失败不同）

### 第 1 轮 EVAL_REPORT
```
case_1 稀疏需求   : ❌ no_premature_generation / missing_clarity_gate
case_2 B类初版    : ✅ （诊断~1.0 / 改动~0.5 / 补齐约束示例）
case_3 角色压测   : ✅
case_4 定稿终止   : ✅
通过率 = 3/4
```

## 2. 双裁判对比实验（C 模式 blind vs B 模式自裁判）

对 case_2 R1 的真实输出，用**同一 rubric、只差上下文暴露**，分别派两个裁判子 Agent：

| 维度 | C 模式 blind（只看输出+维度） | B 模式自裁判（带候选上下文） |
|---|---|---|
| shows_gap_diagnosis | 1.0（"明确列出缺失项"） | 1.0（"明确指出了三处缺失"） |
| marks_changes | 0.5（"仅笼统说明补齐了…"） | 0.5（"笼统概括，未做 before→after"） |

**结论：在这条明确的样本上，盲评与自评一致。** 独立裁判并未给出更高/更低分。

---

## 3. 边界样本对照（验证"分歧只在模糊处"）

为确认独立裁判的价值边界，再测两类构造样本：

**(a) 明显弱样本**（直接给优化版、零诊断）：
| 维度 | C blind | B 自裁判 |
|---|---|---|
| shows_gap_diagnosis | 0.0 | 0.0 |
| marks_changes | 0.0 | 0.0 |
→ 两者一致判 0。

**(b) 半吊子诊断样本**（"你初版比较单薄，我充实了结构和约束" + 优化版，无具体缺失清单、无 before→after）：
| 维度 | C blind | B 自裁判 |
|---|---|---|
| shows_gap_diagnosis | 0.5（"仅一句带过缺失"） | 0.5（"仅以'比较单薄'带过"） |
| marks_changes | 0.5（"笼统说充实结构约束"） | 0.5（"笼统说明改动"） |
→ 两者仍一致（均 0.5）。

**结论：在本模型家族上，盲评与自评在所有被测样本上分数完全相同。** 详见第 8 节。

## 4. 优化器修订（→ candidate_v2_c）

**改动日志**
- [`no_premature_generation`+`missing_clarity_gate`] 原问题：信息稀疏时直接生成 → 改法：Workflow 第 2 步加【澄清门】，缺失场景/受众/卖点任一项先问 ≤3 问，严禁先生成 → 预期 case_1 通过
- [`终止条件`] 原问题："询问修改意见直到满意"易无限追问 → 改法：明确"用户说定稿即停止" → 预期 case_4 保持通过

## 8. 分数曲线与关于"独立裁判更严"的诚实结论

```
轮次   通过率    主要失败标签
R1     3/4      no_premature_generation / missing_clarity_gate
R2     3/4      clarification_over_trigger（过触发回归）
R3     4/4      （无）
```

**闭环机制可跑通**：同一段原始提示词，经 2 轮"评测报告 → 优化器"迭代（中途还修掉了一个过触发回归），回归通过率 **3/4 → 3/4 → 4/4**，且每次改动都可追溯到失败标签。

**关于"独立裁判更严/更稳"——本测试无法证实，必须如实说明**：
- 第 2、3 节的双裁判对比显示：在本模型家族上，blind 裁判与自裁判在**所有被测样本（明确好 / 明确差 / 半吊子）上分数完全一致**。
- 原因：WorkBuddy 内裁判与被测同属一个模型家族，所谓"独立"只是**上下文隔离**，模型本身的评分倾向没变。自评宽松偏差要到**换一个不同家族的 `JUDGE_MODEL`** 时才会显现/被消除。
- 因此：README 中"C 档分数比 B 档更严格、波动更小"这条性质，**仅对真·双模型（外部 `run_loop.py` 填 `JUDGE_MODEL`）成立**；WorkBuddy 内测只能证明 C 档**方法论**（角色隔离的 blind 裁判能正确运行、可复现），不能证明偏差消除。

## 9. 测试过程中踩到的坑（在 B 档 7 坑基础上）

1. **同模型自评偏差无法在 WorkBuddy 内证伪/证实**：双裁判分数一致，因同家族。要证 C 档偏差消除需外部 `JUDGE_MODEL`（真跨家族）。（B 档坑 #1 的延伸）
2. **澄清门过触发（本次实锤）**：candidate_v2 把"用户给的初版提示词"也当空白需求拦下，导致 case_2 回归。优化器需显式区分"空白需求类 vs 待优化初版类"。B 档坑 #4 从"可能"变"实测"。
3. **非确定性再次确认**：同一 candidate_v1，本次 R1 的 case_2 已自带缺口诊断（PASS）、case_4 已停止追问（PASS），与 B 档记录 R1（弱诊断、弱终止）不同。同一候选不同次跑结果可差 2 个用例。验收应固定温度或关键用例跑 ≥2 次。
4. **子 Agent 隔离不彻底**：执行器常自发加 emoji（🪓）、寒暄，需在指令中"禁用 emoji"。虽不影响本次 rule 判定，但污染纯净角色输出。
5. **blind 裁判模板必须 rubric 化**：独立裁判若只说"严格打分"会飘；必须给它和 B 模式**完全相同的 rubric 与分值锚点**，否则 B/C 对比失去控制变量意义。
6. **多轮用例需拼接**：case_3/case_4 仍是把多轮塞进单条输入模拟；真实 harness 应维护对话历史。
7. **防过拟合未验**：仅用已知 4 组，未跑 `eval-spec.md` 第 4 节 unseen 集；优化可能只针对这 4 组生效。最终验收应补 unseen 集。

## 10. 如何使用本记录

- 想复现：见同目录 `c_tier_harness.md`（独立 blind 裁判子 Agent 模板 + 规则评分片段 + 循环步骤）。
- 想跑**真·双模型 C 档**（跨家族独立裁判，验证偏差消除）：在本地跑 `scripts/run_loop.py`，填 `JUDGE_MODEL` 为不同于 `MODEL` 的服务商模型（或用 `--judge-model` 参数）；裁判 + 优化器走 `JUDGE_MODEL`，执行器留 `MODEL`。
- 候选原文：`../../b_tier_test/candidate_v1.md`、`./candidate_v2_c.md`、`./candidate_v3_c.md`。
