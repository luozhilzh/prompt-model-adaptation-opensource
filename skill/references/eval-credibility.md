# Phase 2 — 评测可信度脚手架（Eval Credibility）

> 路线 A 的第三阶段（升级路线文档 · Phase 2 · 评测可信度）。
> 目标：专家问"你尺子准吗"时，能拿出**数字**而非只说"我们标了诚实边界"。
> 本文是**离线可搭的脚手架**：模板、报告格式、离线工具都已就位；真机数字需配置 `OPENAI_API_KEY` 后跑真实评测。

---

## 0. 为什么需要这一层

A→D 四档闭环能产出"4/4 通过"，但"4/4"本身不可信，除非回答三个问题：

1. **我的裁判稳吗？**（同一条样本，裁判这次说 pass、下次说 fail？）→ 裁判自洽投票 + 方差
2. **我的管道比基线强吗？**（zero-shot / 人写一次 / 通用模板，lift 是多少？）→ baseline 对比
3. **我的每一招都"挣到了位置"吗？**（关掉澄清门 / 终止 / XML / few-shot，分数掉多少？）→ ablation 研究

Phase 2 就是把这三件事从"口头声称"变成"可复现的报告格式"。

---

## 1. 技术一：裁判自洽投票（Judge Self-Consistency Voting）

**做法**：对每条用例，让裁判（或 K 个独立裁判）独立判 K=3~5 次，取多数判 pass；同时输出稳定性 / 方差报告。

**价值**：把单点判分变成"带置信度的判分"。一条样本若 K 次里有 2 次 fail，即使多数判 pass，也应标"低置信"，不计入硬达标。

### 离线可跑工具

`scripts/eval_credibility.py` 接收一个用例的 K 份裁判打分 JSON（格式同 `run_loop.py` 产出的 `report_roundN.json` 的 `dimensions` 列表），输出方差报告：

```bash
# 离线自测（生成 mock K 份打分并直接打印方差报告，无需 API）
python scripts/eval_credibility.py --demo

# 真实用法：传入 K 份报告（每份是 {case_id: [dim_scores]} 的 JSON）
python scripts/eval_credibility.py report_judge1.json report_judge2.json report_judge3.json
```

### 方差报告格式（建议）

| 用例 | K 次 pass 数 | 通过率稳定性 | 维度分均值 μ | 维度分标准差 σ | 置信 |
|---|---|---|---|---|---|
| case_1 | 5/5 | 稳定 | 1.00 | 0.00 | 高 |
| case_3 | 3/5 | 波动 | 0.81 | 0.18 | 低（需复核） |

> 判读：σ 越大 → 该用例判分越不可信 → 不能单凭一次 pass 宣称达标。
> 真机：用 `run_loop.py` 对同一候选跑 K 次（调温度 / 换裁判 seed），收集 K 份 `report_roundN.json` 喂给本工具。

## 3. 技术三：ablation 研究（每招都挣到了位置）

**做法**：逐个"关掉"一项技术（澄清门 / 终止 / XML 标签 / few-shot），重跑闭环，测 delta，证明每招都贡献了分数，反制"只是堆砌变长"。

### ablation 表模板（建议）

| 关掉的技术 | 平均通过率（关前→关后） | Δ | 结论 |
|---|---|---|---|
| 澄清门 | 4/4 → 2/4 | -2 | 挣到了位置 |
| XML 标签包裹 | 4/4 → 3/4 | -1 | 挣到了位置 |
| few-shot 对齐 | 4/4 → 3/4 | -1 | 挣到了位置 |

> 判读：任何一项 ablation 后分数不掉 → 该技术是装饰，应移除或重写。
> 真机：在 `run_loop.py` 优化器里临时禁用对应约束，跑闭环收集 Δ。

---

## 4. 诚实边界（必读）

- **本脚手架不产生可信数字**：`eval_credibility.py --demo` 的"方差报告"由 mock 打分生成，仅验证**报告格式与工具能跑**，不代表任何真实裁判稳定性。
- **真机数字需两件事**：① 配置 `OPENAI_API_KEY` 跑真实评测（收集 K 份 / baseline / ablation 数据）；② 足量 **unseen** 用例集（不能只在已知 4 组上刷分，否则过拟合）。
- **方差 ≠ 公正**：裁判自洽只能证明"判分稳定"，不能证明"判分标准对"。baseline / ablation 才是证明"管道有价值"的关键。
- **Phase 2 是守门，不是装饰**：它回答专家对方法学的质疑；没有它，"4/4"只是内部自嗨。

---

## 5. 与路线图其他阶段的关系

- 依赖 Phase 1（有第二任务 / unseen 后，baseline 对比才更有说服力）。
- 与 Phase 3（优化器智能化）互补：Phase 3 让优化器更聪明，Phase 2 证明"聪明"真的带来了分数。
- 路线 A 最小可信发布 = Phase 0 + Phase 1；Phase 2 让 claims 经得起专家审查（按需补）。
