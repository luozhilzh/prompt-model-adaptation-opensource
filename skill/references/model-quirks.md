# 常见模型家族癖好与适配要点

> 经验性归纳（非基准测试）。适配具体版本时以实跑回归为准；未知版本号务必标注不确定性。

---

## DeepSeek（V3 / R1 / R1-Distill）
- **弱点**：输出偏长、易"好心加戏"、偶附免责声明。R1 有独立思考区（thinking）。**官方特别提示：R1 系列建议避免使用 system prompt，将指令放在用户提示中**——经 system 角色传关键指令可能行为异常或被忽略；R1 偶发"思维绕过"（输出空行后直接给结论、跳过推理）。
- **适配**：收敛开场与输出长度；强化"不得切换身份"；限定"只输出代码块 + ≤1 句引导"；**R1 不要把关键指令压在 system 角色**（放 user 提示更稳）；数学/推理任务加 "请逐步推理，并将最终答案放在 \boxed{} 内"；防思维绕过可强制以思考标记开头；V3 行为接近通用模型，可按常规约束。
- **温度**：R1 取 0.5–0.7（官方建议 0.6，防无休止重复或不一致）；V3 默认 0.7，0.1–1.0 区间表现稳定；数学/精确任务可降到 0.3–0.5。
- **注意**：基于公开资料（DeepSeek 官方 GitHub 使用建议 + 社区实测）归纳，非本仓库 --multi 实测；经 OpenAI 兼容网关时 system/user 角色由 harness 决定，适配 R1 时优先把约束写进 user 提示并实跑校准。

## GLM（含 GLM-4.5 / 4.6 / 4.7 / 5.x）
- **弱点**：否定/模糊指令遵循偏弱（偏好"精准引导 > 详尽描述"——给明确"任务类型 + 核心要求"优于大段描述）；爱寒暄、易为"热心"破功追加说明；长输出偶发重复（需 repetition / presence 惩罚）。
- **适配**：用精准指令而非详尽描述；**System Prompt 放角色 / 语言风格 / 输出格式（官方推荐做法，与 R1 不同可放心用）**；显式"只输出结果，不展示推理"（官方"隐藏推理过程"技巧）；必须式措辞 + 禁寒暄 / 额外解释；锁角色"不破功"；限长（控制信息密度、每句单核心）。
- **温度**：按系列差异大——GLM-4.5 默认 0.6、GLM-4 默认 0.75、GLM-4.6 / 4.7 / 5.x 默认 1.0（范围 0–1.0，部分 4.6 支持到 2.0）；格式 / 代码任务取 0.3–0.5 更稳，创意 0.8–1.0。温度与 top_p 二选一调，勿同时大幅调整。
- **注意**：基于公开资料（智谱官方 bigmodel 文档 + GLM-4.5 提示词实战指南）归纳，非本仓库 --multi 实测；具体版本（4.5 / 4.6 / 5.x）默认温度与 system 角色支持需实跑校准。

## Qwen（Qwen2.5 / Qwen3.x）
- **弱点**：Qwen3 **默认开启 thinking 模式**（`<think>...</think>` 包裹推理），开启时易把推理带进回复；偶加 preamble；指令遵循总体较好。
- **适配**：thinking 收口——要么关 thinking（API 侧 `enable_thinking=False` 或用户消息 `/no_think` 软开关，回复干净无 `<think>` 块），要么要求"思考内部化、回复只含结果"；轻量禁寒暄；锁角色。约束可比 GLM 轻。多轮对话历史只保留最终输出、剥离 `<think>` 块。
- **温度**：**严禁贪婪解码（temperature=0）**——官方明确会导致无尽重复与质量骤降；Qwen3 thinking 模式取 0.6、非 thinking 取 0.7（top_p 0.95 / 0.8，top_k 20），确定性任务也不要取 0、用 0.6 / 0.7 + 强格式约束兜底；Qwen2.5 可 0.3–0.5。
- **注意**：基于公开资料（Qwen3 官方 Model Card / 阿里云 deep thinking 文档）归纳，非本仓库 --multi 实测；Qwen3 的 thinking 默认开启与软硬开关、具体版本号需实跑校准。

## Hunyuan（混元：hunyuan-t1 / turbos / a13b / standard-256K / large / lite）
- **弱点**：偏长爱铺垫、易附"作为 AI"免责声明或自我介绍；推理版（T1 / a13b 混合推理）开启思考时易把推理带进回复。
- **适配**：禁铺垫 / 禁自我介绍；不附免责声明；必须式；限长；用结构化约束（Markdown 表格 / 固定格式）提升输出规范性；复杂任务加"请分步骤思考"提逻辑准确率。推理版需 thinking 收口（思考内部化、回复只含结果；a13b 可切"慢思考"关思考出干净结果）。
- **温度**：默认 0.7；代码 / 精确任务 0.3–0.5，常规对话 0.7–0.9，创意 1.0–1.5（范围 0–2）。推理版（T1）输出空间大（可达 64K），长推理任务给足 max_tokens。
- **注意**：基于公开资料（腾讯云 Hunyuan 文档 + 第三方最佳实践）归纳，非本仓库 --multi 实测；具体版本（t1 / turbos / a13b）是否带推理、思考开关与默认温度需实跑校准。

## Gemini（Gemini 1.5 / 2.0 / 2.5 / 3 Pro·Flash）
- **弱点**：指令遵循强但偏"热心"，易加 preamble / 免责铺垫、过度解释；长上下文（1M+）下关键约束易被稀释，需重复锚定；安全过滤器偶发对提示词内容误拒；Gemini 2.5/3 系列默认开启内部 thinking，一般无需在回复里显式要求逐步推理（否则反而冗余）。
- **适配**：禁寒暄 / preamble / 免责；开头即给产物（代码块 / 模板）+ ≤1 句引导；关键约束放系统指令开头并显式重复；长文档/数据放提示词前部、具体指令/查询放末尾（官方称可提升响应质量）；用 XML 标签（如 <instructions> <context>）隔离指令与数据，降低混淆与误注入噪声；长文任务明确要求"只输出结果，不解释过程"。
- **温度**：0.4–0.7；纯格式 / 模板任务取低值；Gemini 3 默认偏精简，需"健谈"人设须显式要求。
- **注意**：基于公开行为归纳（Google 官方 Prompting guide + 社区），非本仓库 --multi 实测；具体版本（如 2.5-flash vs pro vs 3）与 thinking 开关需实跑校准；安全误拒风险在红队门禁下可被捕获。

## Claude（Claude 3.5 / 3.7 / 4 Sonnet·Opus，含 Fable/Mythos 新系列）
- **弱点**：指令遵循与角色保持均强，但"乐于助人过度"——爱客套（"很高兴帮你…"）、附长篇解释与 caveat；扩展思考（extended thinking）开启时会分配独立推理预算、推理内部化不暴露，但若要求显式 CoT 会冗余；边缘安全用例可能过度拒绝。
- **适配**：锁角色"不破功"（本身强，显式锚定更稳）；用清晰直接的指令而非礼貌式请求（官方：直接 "Be concise. Omit preamble" 优于 "please try to be concise"）；禁客套 / 免责声明 / 长篇解释；限定只输出目标产物 + ≤1 句；低温更守格式；用 XML 标签（<instructions> <examples>）区分指令/数据/示例；长文档放提示词前部、查询放末尾（官方称可提升质量达 30%）。
- **温度**：0.2–0.5（低温仍流畅）；确定性任务取 0；创意/头脑风暴 0.7–1.0。扩展思考如需干净输出，明确要求"只给最终答案，不展示推理"。
- **注意**：基于公开行为归纳（Anthropic 官方 Prompting guide + 社区），非本仓库 --multi 实测；具体版本与思考模式需实跑校准；过度拒绝在红队门禁下可被捕获，良性适配应正常遵从。

## 通用排序参考（定性，仅观感）
- 指令遵循由强到弱大致：Claude ≈ Gemini ≈ Qwen ≈ DeepSeek > Hunyuan ≈ GLM。
- 角色保持：Claude/Qwen/DeepSeek 稳；Gemini 良好但需显式锚定；GLM 易破功；Hunyuan 易附免责。
- 输出长度：六家均偏长倾向，均需限长约束；Gemini/Claude 尤爱客套与过度解释，需明禁。
- 中文语感：六家均强，无需特别处理。
- 特殊风险：Claude/Gemini 注意客套/过度解释与扩展思考溢出；Qwen/DeepSeek 推理版 thinking 溢出；GLM 寒暄/破功；Hunyuan 铺垫/免责；Gemini 安全过滤器偶发误拒（适配提示词内容时留意）。
