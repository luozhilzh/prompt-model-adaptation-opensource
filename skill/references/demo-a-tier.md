# Demo — A 档自评审闭环（一次实跑记录）

本文件是 `prompt-model-adaptation` skill 的 **A 档自评审** 的一次真实演示记录：用用户最初那段「AI Prompt 教练」原提示词做候选，按 `eval-spec.md` 自评 → 用 `optimizer-meta-prompt.md` 修订 → 再评，展示回归通过率从 0/4 升到 4/4。

> 诚实边界：以下自评基于提示工程判断，非目标模型真实跑分。B/C 档会用真实调用 + 独立裁判消除自评宽松。

---

## 候选提示词（原版，节选关键特征）

- Workflow ①：「谐趣精炼地介绍自己，询问用户想要撰写一个什么样的提示词」
- Workflow ②：「运用三板斧技巧，根据用户输入撰写高质量的提示词……深度思考后给出更好的提示词」
- Workflow ③：「询问用户修改意见，直到用户满意为止」
- 输出模板含 `# 初始化`（生成提示词内的角色初始化），末尾又有一节 `## Initialization`（教练自身开场）——两个"初始化"并存
- 无澄清门、无明确定稿信号

---

## 🔁 第 1 轮 EVAL_REPORT（按 eval-spec 自评）

| 用例 | 预期 | 实际 | 结果 | 失败标签 |
|---|---|---|---|---|
| case_1 稀疏需求 | 触发澄清门，反问 ≤3 问 | 直接按输入生成提示词 | ❌ | `missing_clarity_gate` |
| case_2 B类初版 | 先列缺口诊断 + 标注改动 | 直接"深度思考后给更好的"，无结构化诊断 | ❌（弱） | `missing_diagnosis` |
| case_3 角色压测 | 保持教练身份、不附免责 | 双"初始化"易混淆，压测下可能串角色 | ❌（风险） | `role_confusion` |
| case_4 定稿终止 | 定稿后停止追问 | "直到满意"无明确终止，可能继续追问 | ❌（弱） | `no_termination` |

**第 1 轮得分：0 / 4 通过。**

---

## 🛠 优化器修订（喂入 optimizer-meta-prompt）

**改动日志：**

- [`missing_clarity_gate`] 原问题：需求稀疏时直接生成 → 改法：Workflow 新增澄清门，缺「场景/身份/输出形态/约束」任一项先问 ≤3 问 → 预期 case_1 通过
- [`missing_diagnosis`] 原问题：无结构化诊断 → 改法：B 类输入先列缺口诊断再给优化版 + 改动说明 → 预期 case_2 通过
- [`role_confusion`] 原问题：双初始化歧义 → 改法：明确 `# 初始化` 属生成提示词、教练自身开场单独标注，加"不扮演生成角色 / 不附免责" → 预期 case_3 通过
- [`no_termination`] 原问题：无终止 → 改法：加定稿触发"定稿/导出 → 输出最终版并停止" → 预期 case_4 通过

---

## 🔁 第 2 轮：改进版提示词（核心 diff）

- 开场：`谐趣精炼地介绍自己` → `用 1–2 句话介绍自己是"三板斧提示词教练"，并询问想从零写还是优化已有提示词`
- 新增步骤 2（澄清门）：`若缺场景/身份/输出形态/约束任一项，先问 ≤3 个问题再生成`
- 步骤 3：增加 `B 类输入先按三板斧诊断缺口，再给优化版 + 改动说明`
- 注意段：`不要扮演生成提示词里的角色，不附"我是 AI"免责声明`
- 步骤 4（定稿）：`用户说"定稿/导出"即输出最终版并提示可复制，停止追问`

### 第 2 轮 EVAL_REPORT

| 用例 | 结果 |
|---|---|
| case_1 稀疏需求 | ✅ 触发澄清门 |
| case_2 B类初版 | ✅ 先诊断后优化 + 改动说明 |
| case_3 角色压测 | ✅ 保持教练身份、无免责声明 |
| case_4 定稿终止 | ✅ 定稿后停止 |

**第 2 轮得分：4 / 4 通过。**

---

## ✅ 结论

同一段原提示词，经 1 轮「评测报告 → 优化器」闭环，回归通过率 **0/4 → 4/4**，且每次改动都**可追溯到失败标签**（不是瞎改）。这证明 A 档自评审机制有效——把"人拍脑袋优化"变成了"反馈驱动的定向修订"。
